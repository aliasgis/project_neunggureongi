# 버전 정책

> 관련: [브랜치 전략](branch-strategy.md) · [이슈·커밋·PR 작성 규칙](message-convention.md)

## 1. 형식

```
x.y.z
└┬┘ └─ build : 출시할 때마다 +1. x.y 가 바뀌어도 0 으로 돌리지 않는다
 └──── 판(版) : 관리자가 판단해 연다
```

```
1.0.0 → 1.0.1 → 1.0.2 → (판올림) 1.1.3 → 1.1.4 → (판올림) 2.0.5
```

## 2. 판 — `x.y`

- **판올림 시기는 관리자가 판단한다.** 정해진 기준표를 두지 않는다.
- 판올림 때는 **`x.y` 만 바꾼다.** build 는 이전 출시에서 이어진다.
- `x` 를 올릴지 `y` 를 올릴지도 관리자가 정한다. 큰 전환이면 `x`, 그 밖에는 `y` 를 쓰는 것을 권한다.
- **판을 올린 이유를 남긴다.** 판을 올리는 출시의 태그 메시지와 Release 노트 첫 줄에 한 줄로 적는다.
  ```
  v1.1.3 (2026-12-10) — 1.1 판올림: PostGIS 다중 연결 도입
  ```
  기준이 없는 대신 기록을 남겨, 나중에 왜 그때 판이 바뀌었는지 알 수 있게 한다.

## 3. build — `z`

- **`main` 에 출시해 태그를 달 때만** 1 씩 올린다. `develop` 머지나 개발 중 빌드로는 올리지 않는다.
- **0 으로 돌리지 않는다.** 판이 바뀌어도 계속 쌓인다.
- build 는 전체에서 한 번만 쓰이므로 **build 번호만으로 출시가 하나로 특정된다.**
- 긴급 수정도 따로 "패치" 번호를 두지 않고 다음 build 로 출시한다.
- 오래된 판에 긴급 수정을 내도 번호는 전체에서 이어진다.
  예: `1.1.6` 출시 뒤 `release/1.0` 에 긴급 수정을 내면 `1.0.7`.

## 4. 기준점 — `1.0.0`

| | |
|---|---|
| `v1.0.0` | 현재 `main` 의 `89afb00` (build 0). 이 정책 이전에 배포된 코드 |
| 첫 정식 출시 | `1.0.1` — 브랜치 전략·메시지 규칙·버전 정책이 처음 함께 들어가는 출시 |

`v1.0.0` 태그는 `89afb00` 이 실제로 배포한 1.0.0 이 맞는지 확인한 뒤 단다.

## 5. 버전이 쓰이는 곳

| 곳 | 형식 | 예 |
|---|---|---|
| 코드 | `version.py` 한 곳 | `__version__ = "1.0.1"` |
| 태그 | `v<x.y.z>` (annotated) | `v1.0.1` |
| 출시 라인 | `release/<x.y>` | `release/1.0` |
| 마일스톤 | `<x.y.z>` — 다음 출시 | `1.0.1` |
| `develop` 작업 제목 | `[<x.y>]` — 현재 판 | `[1.0] feature: …` |
| 출시·긴급 수정 제목 | `[<x.y.z>]` — 정확한 버전 | `[1.0.1] release: …` |

- 다음 출시 번호는 **지난 태그의 build + 1** 이므로 미리 알 수 있다. 마일스톤은 이 번호로 만든다.
- 판올림이 정해지면 다음 마일스톤 이름과 `develop` 작업 제목의 `[x.y]` 를 새 판으로 바꾼다.

### 코드의 버전 번호

지금은 `1.0.0` 이 `app.py`(FastAPI `version`, 로그인 화면 `VERSION`)와 `start_server.ps1` 에 따로 적혀 있다.
첫 출시 전에 `version.py` 하나를 만들고 나머지가 그 값을 읽게 바꾼다 (`fix/*`).

## 6. 출시할 때

1. 지난 태그를 확인해 다음 번호를 정한다: `git describe --tags --abbrev=0` → `v1.0.4` 면 다음은 `1.0.5` (판올림이면 `1.1.5`).
2. `release/<x.y>` 에서 `version.py` 를 그 번호로 올린다.
3. `main` 에 머지한 커밋에 태그를 단다.
   ```bash
   git tag -a v1.0.5 -m "v1.0.5 (YYYY-MM-DD) — <주요 변경>"
   git push origin v1.0.5
   ```
4. 같은 이름의 마일스톤을 닫고 GitHub Release 를 만든다.
